# 식단 수집 상태와 보존 정책

- `last_checked`: 매번 수집을 시도한 한국 시간. 화면은 30시간 이상 점검이 없으면 경고한다.
- `updated_at`: 유효한 대상 주간 식단을 수집했고 메뉴 내용 또는 표시 날짜가 바뀐 시각. 내용이 같으면 유지한다.
- `crawl_status`: 모든 식당 성공은 `success`, 일부 성공은 `partial`, 전부 실패는 `failed`.
- `shop_status`: 식당별 상태, 점검 시각, 마지막 성공 시각. 실패한 식당은 이전 식단을 유지하며 화면에 식당 이름을 안내한다.
- 날짜와 요일은 대상 주간(월~일)에 속해야 한다. 공휴일의 단축 주간과 연말·연초 주간을 허용한다. 일요일 다음 주 수집은 다음 월요일이 속한 주간을 검증한다.
- 오늘 날짜 또는 식당별 오늘 메뉴가 없으면 휴무·미등록 여부를 확인하라는 안내를 표시한다. 빈 메뉴만으로 휴무를 단정하지 않는다.
- 저장은 같은 폴더의 임시 파일에 기록·동기화한 후 교체한다. 교체 실패 시 기존 파일을 보존하고 실패로 종료한다. 기존 JSON이 손상되어 읽히지 않으면 덮어쓰지 않는다.
- 부분 실패도 종료 코드 1을 반환한다. Actions는 저장된 상태를 커밋한 뒤 실패를 보고한다. 파일 저장 자체가 실패하면 새 상태를 기록할 수 없으므로 Actions 로그를 확인해야 한다.

검증: `python -m unittest discover -s tests -v`, `node tests/test_meal_status.cjs`.

원본 사이트와 메뉴가 동일한지, 휴무인지, 원본에서 일부 끼니만 누락됐는지는 별도의 운영 정보 없이는 확정할 수 없다. 주간 데이터의 유효성과 수집 성공 여부를 구분해 운영한다.
